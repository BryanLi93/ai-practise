# 真正值得复盘的坑

这里只保留会影响正确性、事务或流式协议的问题。函数漏接参数、漏写 `return`、复制代码后变量名没改等小错误，统一归到“重构后验证完整调用链”，不再逐条记流水账。

## 1. “最近 N 条”不能写成 `ASC + LIMIT N`

**问题**

对话不超过 N 条时一切正常；消息变多后，模型一直看到最早的几条，新消息反而消失。

**根因**

`ORDER BY id ASC LIMIT N` 取到的是 id 最小的 N 条，也就是最旧消息。这里其实有两个要求：先选出“最新 N 条”，再把它们按正常时间顺序交给模型。

**修复**

```python
stmt = (
    select(Message)
    .order_by(Message.id.desc())
    .limit(limit)
)
messages = list(reversed(result.scalars().all()))
```

先用 `DESC + LIMIT` 留下最新消息，再反转成从旧到新的顺序。

**记住**

“选哪几条”和“最后怎么排列”是两个问题，不要试图用一个排序同时解决。

## 2. 历史回答里的引用编号会污染本轮引用

**问题**

上一轮 assistant 的答案有 `[1]`、`[2]`，本轮新 context 也从 `[1]` 开始。模型可能引用旧编号，但 API 返回的 `sources` 却是本轮来源，导致编号和原文对不上。

**根因**

历史记录和当前检索结果承担不同职责：历史只用于理解指代，当前 context 才是事实来源。把两者混进同一个编号空间后，模型无法区分。

**修复**

- 拼接历史前删除旧引用：`re.sub(r"\[\d+\]", "", history)`。
- 在 system prompt 中明确：历史只能帮助理解问题，不能作为事实来源，也不能被引用。

**记住**

多轮 RAG 里，聊天历史不是知识库证据。引用编号必须只属于当前检索结果。

## 3. 先写数据库、后跑 RAG，会留下半成品

**问题**

旧流程先创建会话并提交，再调用 embedding 和 LLM。RAG 失败后，空会话已经留在数据库里；一次问答还被拆成多次 commit。

**根因**

事务边界按函数划分了，而不是按“一次完整问答”划分。

**修复**

流程改成：

```text
读取历史 -> 改写 -> 检索 -> 生成 -> 创建会话 -> 写入两条消息 -> commit
```

外部调用阶段不写数据库。全部成功后才集中写入，一次 commit 完成。

**记住**

一个用户动作应该对应一个完整事务。也不要在等待慢速 LLM 时提前开启并长期占用写事务。

## 5. 异步生成器里的错误，可能在 HTTP 200 之后才发生

**问题**

流式接口收到不存在的 `conversation_id` 时，本来应该返回 404，客户端却先收到 200，然后连接中断。

**根因**

带 `yield` 的异步生成器是惰性的。调用 `handle_chat_stream(...)` 只会得到生成器对象，函数体还没有执行。如果直接交给 `StreamingResponse`，FastAPI 会先开始响应，再从生成器取数据；此时抛出的异常已经来不及改状态码。

**修复**

router 在创建 `StreamingResponse` 前先手动取第一帧：

```python
agen = handle_chat_stream(...)
first_frame = await agen.__anext__()
```

这样会话校验和检索先执行。开流前失败还能映射成 404/502；开流后生成失败只能发送一条 SSE `error` 帧。

**记住**

流式接口要明确区分“响应开始前”和“响应开始后”的错误处理，不能只写一套异常逻辑。

## 6. 一个网络数据块不等于一条 SSE 消息

**问题**

前端直接对每次 `reader.read()` 的结果做 `JSON.parse`，偶尔会报解析错误，中文也可能乱码。

**根因**

网络可能把一条 SSE 消息拆成多个块，也可能把多条消息放在同一个块里。UTF-8 中文字符本身也可能被拆在两个块之间。

**修复**

```javascript
buffer += decoder.decode(value, { stream: true });

let index;
while ((index = buffer.indexOf("\n\n")) !== -1) {
  const raw = buffer.slice(0, index);
  buffer = buffer.slice(index + 2);
  // 只在拿到完整 SSE 消息后再解析 data
}
```

**记住**

网络块只是传输单位，不是业务消息边界。读流时必须先缓冲，再按协议分隔符拆帧。
